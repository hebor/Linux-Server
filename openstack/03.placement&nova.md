# Placement

## Placement概述

早期的OpenStack架构中是没有Placement组件的，Placement组件服务主要用于跟踪资源（即动态资源监控）。Placement组件服务使其他项目能够跟踪自己的资源。这些项目可以通过Placement HTTP API将自己的资源注册到Placement组件服务或从Placement组件服务中删除自己的资源。Placement组件服务起源于Nova组件，因此，Placement组件中的大部分功能都是由Nova的需求驱动的。但是，该功能被设计为足够通用，可供任何需要管理资源选择和消耗的服务使用。

Placement组件服务提供了placement-api，一个标准的WSGI脚本，用于使用Apache、nginx或其他支持WSGI的Web服务器运行服务。placement-api作为标准的WSGI脚本，提供模块级别application属性。这意味着可以在许多不同的服务器上运行它。通过placement-api接口可以实现跟踪project里的资源，然后将跟踪的资源同步到数据库，因此Placement组件本身并不复杂，仅仅是提供了动态资源监控的功能

## Placement部署

### 一、先决条件

1. 数据库配置

   ```bash
   # 1.登录MariaDB
   [root@controller ~]# mysql -uroot -predhat
   
   # 2.创建名为placement的数据库
   MariaDB [(none)]> CREATE DATABASE placement;
   
   # 3.创建placement账户并授权
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON placement.* TO 'placement'@'localhost' IDENTIFIED BY 'openstack_placement';
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON placement.* TO 'placement'@'%' IDENTIFIED BY 'openstack_placement';
   MariaDB [(none)]> FLUSH PRIVILEGES;
   ```

2. 创建Glance服务凭证

   ```bash
   [root@controller ~]# source admin-openrc
   [root@controller ~]# openstack user create --domain default --password openstack_placement placement
   [root@controller ~]# openstack role add --project service --user placement admin
   [root@controller ~]# openstack service create --name placement --description "Placement API" placement
   [root@controller ~]# openstack service list
   ```

3. 为服务实体创建API EndPoint

   ```bash
   [root@controller ~]# openstack endpoint create --region RegionOne placement public http://controller:8778
   [root@controller ~]# openstack endpoint create --region RegionOne placement internal http://controller:8778
   [root@controller ~]# openstack endpoint create --region RegionOne placement admin http://controller:8778
   ```

### 二、安装配置

1. 安装Placement

   ```bash
   [root@controller ~]# yum install -y openstack-placement-api
   ```

2. 修改Placement配置文件，连接数据库

   ```bash
   [root@controller ~]# vim /etc/placement/placement.conf
   [placement_database]
   connection = mysql+pymysql://placement:openstack_placement@controller/placement
   [api]
   auth_strategy = keystone    # 指定api接口的认证方式，通过keystone认证
   [keystone_authtoken]
   auth_url = http://controller:5000/v3
   memcached_servers = controller:11211
   auth_type = password
   project_domain_name = Default
   user_domain_name = Default
   project_name = service
   username = placement
   password = openstack_placement
   ```

3. 初始化placement数据库

   ```bash
   [root@controller ~]# su -s /bin/sh -c "placement-manage db sync" placement
   /usr/lib/python2.7/site-packages/pymysql/cursors.py:170: Warning: (1280, u"Name 'alembic_version_pkc' ignored for PRIMARY key.")
     result = self._query(query)
   [root@controller ~]# mysql -uroot -predhat placement
   MariaDB [placement]> SHOW TABLES;    # 验证placement的表是否正常
   ```

   初始化placement数据库时可能会产生一个Warning告警，声明placement数据库中存在一个会被忽略的主键`alembic_version_pkc`，忽略此告警即可

4. 修改httpd服务

   在OpenStack的Rocky版本种有单独对于Placement API组件服务的说明，由于OpenStack的打包错误，您必须通过将以下配置添加到/etc/httpd/conf . d/00-nova-Placement-API . conf来启用对Placement API的访问

   ```bash
   [root@controller ~]# vim /etc/httpd/conf.d/00-placement-api.conf
   <VirtualHost *:8778>
   ...
     <Directory /usr/bin>    # 此配置需要手动添加，缺省情况下Placement没有这一段配置
       <IfVersion >= 2.4>
         Require all granted
       </IfVersion>
       <IfVersion < 2.4>
         Order allow,deny
         Allow from all
       </IfVersion>
     </Directory>
   </VirtualHost>
   [root@controller ~]# systemctl restart httpd
   [root@controller ~]# systemctl enable httpd
   ```

   此处的HTTP配置文件无论是否修改，似乎不会影响到Placement组件服务本身，但是配置到Nova组件服务时会需要配置Placement相关的内容，即Nova组件服务会有需要调用Placement组件的API服务，如果没有手动修改Placement组件服务的HTTP服务配置，那么Nova组件请求Placement组件API服务时会被拒绝，可查看`/var/log/placement/placement-api.log`错误日志：`AH01630: client denied by server configuration: /usr/bin/placement-api`

5. 执行Placement的状态检查

   ```bash
   [root@controller ~]# placement-status upgrade check    # 执行状态检查
   
   # 一下步骤可以省略不做，OpenStack官方指南会通过一下步骤验证Placement组件，但osc-placement插件版本与Train版本不兼容，导致接口调用失败，无法验证Placement组件的效果
   [root@controller ~]# yum install -y epel-release    # CentOS默认的YUM源中没有pip，需要扩展源EPEL
   [root@controller ~]# yum install -y python-pip    # 安装osc-placement插件之前需要先安装pip
   [root@controller ~]# pip install osc-placement==2.2.0 --index-url https://mirrors.aliyun.com/pypi/simple/    # 使用阿里云镜像源安装osc-placement插件，缺省的源可能会因为无法验证服务器的SSL证书而导致安装失败
   [root@controller ~]# openstack --os-placement-api-version 1.2 resource class list --sort-column name
   +----------------------------+
   | name                       |
   +----------------------------+
   | DISK_GB                    |
   | FPGA                       |
   |...                         |
   [root@controller ~]# openstack --os-placement-api-version 1.6 trait list --sort-column name
   +---------------------------------------+
   | name                                  |
   +---------------------------------------+
   | COMPUTE_DEVICE_TAGGING                |
   | COMPUTE_GRAPHICS_MODEL_CIRRUS         |
   | ...                                   |
   ```
   
   在安装osc-placement插件的步骤上需要比较注意，首先使用YUM安装的软件包是`python-pip`而不是`pip`，其次使用pip安装osc-placement插件时一定要指定2.2.0版本号，以上两点任一一点错误都有可能导致使用osc-placement插件验证时出现错误，无法正常获取到验证结果。使用阿里云镜像源安装插件是因为缺省的源可能会因为无法验证服务器的SSL证书而导致安装osc-placement插件失败
   
   Placement组件服务本身并不像其他组件服务一样提供某一个具体的功能，例如Nova组件提供计算虚拟化功能、Neutron提供网络虚拟化功能，Placement仅用于动态资源监控

# Nova

Nova组件服务提供的最主要的功能是实例的生命周期管理，它提供了

nova-api：用于接收客户端请求，并分析客户端请求的参数是否合法，例如，一个创建虚拟机的请求需要具备vCPU、vMEM、vDisk等参数，nova-api服务需要分析客户端请求是否具备这些参数、参数值是否正常等，所有组件的API服务都部署在Controller节点上

nova-compute：这个服务运行在计算节点上，此服务需要通过Driver对接虚拟化技术，从而实现对虚拟机的管理，例如nova-compute对接KVM虚拟化技术，它需要使用专门用于对接KVM的Driver。在OpenStack逻辑结构图中，nova-compute服务有一个箭头向下指向Hypervisor，即指向虚拟化宿主机，所有的虚拟机都运行在Hyperviros上，nova-compute需要通过Hypervisor来实现对虚拟机实例的管理

nova-schduler：起到资源调度作用，例如客户端要创建一个虚拟机实例时，这个实例将来要运行在哪个计算节点上，就需要通过nova-schduler来调度，nova-schduler有一些filter（过滤器）来帮助选择一个计算节点，通过filter可以选择通过CPU剩余资源、MEM剩余资源、CPU的使用率等阈值作为判断条件来进行调度

nova-conductor：用于解耦数据库。例如客户端向nova-api发起一个创建虚拟机实例的请求，那么关于该实例的一些资源信息就需要写入数据库，此时nova-api会将客户端的请求消息发送到Queue，在通过nova-conductor从Queue中订阅、消费数据消息，再由nova-conductor将实例的资源信息写入nova-database。除了nova-api服务以外，nova组件内的其他一些服务，例如nova-cert、nova-compute等服务也都是将数据先写入Queue，由nova-conductor从Queue中消费数据再写入nova-database的，因此nova-conductor服务的功能就是解耦数据库

nova-cert：与证书相关的数据和操作由nova-cert服务处理

nova-console：通过Web console登录管理实例之前需要先配置VNC，而VNC最终也是调用到了nova-console服务

nova-database：用于关联数据库

nova组件中最重要的服务有4个：nova-api用于接收和响应客户端请求；nova-scheduler通过filter调度选择合适的nova-compute创建客户端需要的实例；nova-compute用于对接Hypervisor从而实现对实例的管理；nova-conductor实现数据库的解耦

但从OpenStack逻辑结构图中还能看到nova组件中还有一个不同的信息，在此前的组件中都没有遇到过，就是nova需要去连接rabbitmq，例如Glance组件中没有用到Queue，此前的配置中也不涉及Queue。在nova组件中，各个服务之间需要通过Queue实现通信，因此在nova的配置文件中需要定义rabbitmq相关的配置

除了nova-compute服务是部署在计算节点上，nova组件中的其他所有服务都是部署在Controller节点上，因此部署nova组件时需要在两个节点上同时部署，首先需要在Controller节点上完成nova节点的API服务以及API服务所对应的EndPoint的创建，其次在计算节点上配置nova-compute，例如通过什么Driver对接什么虚拟化技术，因此在查看OpenStack官方指南的时候，关于nova组件的部署在官方指南上也分为了Controller节点与Compute节点的配置

## Nova部署

### 一、先决条件

1. 数据库配置；正如前文所述，Nova组件的数据库配置在Controller节点上配置

   ```bash
   # 1.登录MariaDB
   [root@controller ~]# mysql -uroot -predhat
   
   # 2.创建名为placement的数据库
   MariaDB [(none)]> CREATE DATABASE nova_api;
   MariaDB [(none)]> CREATE DATABASE nova;
   MariaDB [(none)]> CREATE DATABASE nova_cell0;
   
   # 3.创建placement账户并授权
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'localhost' IDENTIFIED BY 'openstack_nova';
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_api.* TO 'nova'@'%' IDENTIFIED BY 'openstack_nova';
   
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova.*  TO 'nova'@'localhost' IDENTIFIED BY 'openstack_nova';
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova.* TO 'nova'@'%' IDENTIFIED BY 'openstack_nova';
   
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'localhost' IDENTIFIED BY 'openstack_nova';
   MariaDB [(none)]> GRANT ALL PRIVILEGES ON nova_cell0.* TO 'nova'@'%' IDENTIFIED BY 'openstack_nova';
   MariaDB [(none)]> FLUSH PRIVILEGES;
   ```

2. 创建Glance服务凭证

   ```bash
   [root@controller ~]# source admin-openrc
   [root@controller ~]# openstack user create --domain default --password openstack_nova nova
   [root@controller ~]# openstack role add --project service --user nova admin
   [root@controller ~]# openstack service create --name nova --description "OpenStack Compute" compute
   [root@controller ~]# openstack service list
   ```

3. 为服务实体创建API EndPoint

   ```bash
   [root@controller ~]# openstack endpoint create --region RegionOne compute public http://controller:8774/v2.1
   [root@controller ~]# openstack endpoint create --region RegionOne compute internal http://controller:8774/v2.1
   [root@controller ~]# openstack endpoint create --region RegionOne compute admin http://controller:8774/v2.1
   openstack catalog list
   ```

### 二、安装部署

#### Controller节点配置

1. 安装nova软件包

   ```bash
   [root@controller ~]# yum install -y openstack-nova-api openstack-nova-conductor openstack-nova-novncproxy openstack-nova-scheduler
   ```

2. 修改nova配置文件，连接数据库

   ```bash
   [root@controller ~]# vim /etc/nova/nova.conf
   [DEFAULT]
   enabled-apis = osapi_compute,metadata    # 启用的API接口参数
   transport_url = rabbit://openstack:hebor@controller:5672    # 配置连接RabbitMQ的账户、密码、地址
   my_ip = 192.168.0.40    # 配置my_ip选项以使用控制器节点的管理网络IP地址
   use_neutron = true    # 启用对neutron组件服务的支持
   firewall_driver = nova.virt.firewall.NoopFirewallDriver
   
   [api_database]
   connection = mysql+pymysql://nova:openstack_nova@controller/nova_api
   
   [database]
   connection = mysql+pymysql://nova:openstack_nova@controller/nova
   
   [api]
   auth_strategy = keystone    # API的验证通过keystone验证
   
   [keystone_authtoken]
   www_authenticate_uri = http://controller:5000/
   auth_url = http://controller:5000/
   memcached_servers = controller:11211
   project_domain_name = Default
   user_domain_name = Default
   project_name = service
   username = nova
   password = openstack_nova
   
   [vnc]
   enabled = true    # 启用VNC功能，nova-console服务就是专门为VNC提供服务的，只有配置了VNC，才能通过Web Console访问VNC的管理页面
   server_listen = $my_ip    # VNC服务监听的地址
   server_proxyclient_address = $my_ip    # 配置代理的客户端地址。VNC的服务运行在Controller节点上，但实例实际上运行在Compute节点上，客户通过Horizon去访问Web Console时，实际上会先访问到Controller节点上的VNC服务，然后由Controller节点代理访问Compute节点
   
   [glance]
   api_servers = http://controller:9292    # nova组件负责实例的整个生命周期，这其中就包括实例的创建，而创建实例则需要使用image，因此nova还需要与glance组件对接，组件与组件之间的通信全部都是通过API服务进行对接，因此在nova的配置文件里只需要定义glance组件的API即可，最终nova需要从glance上下载image
   
   [oslo_concurrency]
   lock_path = /var/lib/nova/tmp
   
   [placement]    # 专门用于统计资源信息，统计后的信息仍需要通过placement账户进行上传
   region_name = RegionOne
   project_domain_name = Default
   project_name = service
   auth_type = password
   user_domain_name = Default
   auth_url = http://controller:5000/v3
   username = placement
   password = openstack_placement
   ```
   
   nova配置文件中关于RabbitMQ的配置一定要正确，从此前的Nova组件内部服务通信学习中，Nova组件内部服务都需要通过RabbitMQ进行通信

3. 初始化nova数据库

   ```bash
   [root@controller ~]# su -s /bin/sh -c "nova-manage api_db sync" nova
   [root@controller ~]# su -s /bin/sh -c "nova-manage cell_v2 map_cell0" nova
   [root@controller ~]# su -s /bin/sh -c "nova-manage cell_v2 create_cell --name=cell --verbose" nova
   [root@controller ~]# su -s /bin/sh -c "nova-manage db sync" nova
   [root@controller ~]# su -s /bin/sh -c "nova-manage cell_v2 list_cells" nova
   ```

4. 启用nova服务

   ```bash
   [root@controller ~]# systemctl enable --now openstack-nova-api openstack-nova-scheduler openstack-nova-conductor openstack-nova-novncproxy
   ```

#### Compute节点配置

Compute节点的配置文件可以直接复用Controller节点的配置文件，两者的安装步骤也是与其他OpenStack组件的安装步骤基本一致，需要注意的是，Compute节点上必须要能够支持虚拟化技术，所有的实例都是运行在Compute节点上的

1. 安装nova软件包

   ```bash
   [root@compute ~]# yum install -y openstack-nova-compute
   ```

2. 修改nova配置文件

   Controller节点上的Nova配置文件与Compute节点上的Nova配置文件基本上非常相似，仅少量配置存在差异需要手动修改

   相比较Controller节点与Compute节点的配置文件，主要需要修改的两大块部分分别是VNC相关配置和数据库相关配置，从OpenStack逻辑结构图中可以看到，nova-compute节点服务本身是不直接连接数据库的，而是通过Queue和nova-conductor实现与数据库的数据交互，因此nova-compute节点中需要删除所有连接数据库的配置

   ```bash
   [root@compute ~]# scp -r root@controller:/etc/nova/nova.conf /etc/nova/
   [root@compute ~]# vim /etc/nova/nova.conf
   [DEFAULT]
   my_ip = 192.168.0.41    # 修改为Compute节点的管理平面IP
   
   [api_database]
   # connection = mysql+pymysql://nova:openstack_nova@controller/nova_api    # 删除或注释此行
   
   [database]
   # connection = mysql+pymysql://nova:openstack_nova@controller/nova    # 删除或注释此行
   
   [vnc]
   server_listen = 0.0.0.0    # VNC服务监听Compute节点上的所有IP
   novncproxy_base_url = http://controller:6080/vnc_auto.html    # 指定了用户通过浏览器访问虚拟机VNC控制台的代理服务入口地址。通过Horizon点击VNC服务时会弹出此链接
   ```

3. 完成安装

   ```bash
   [root@compute ~]# egrep -c '(vmx | svm)' /proc/cpuinfo    # 确认Compute节点是否支持KVM虚拟化
   [root@compute ~]# lsmod | grep kvm    # 检查Compute节点是否已加载KVM模块
   
   # 启用服务
   [root@compute ~]# systemctl enable --now libvirtd openstack-nova-compute
   ```

   在OpenStack官方指南中有说明，当egrep指令返回的值为1或更大，则Compute节点支持硬件辅助的虚拟化，通常不需要额外的配置。若egrep指令返回的值为0，则Compute节点不支持硬件辅助的虚拟化，此时必须配置libvirt使用QEMU而不是KVM

   ```bash
   [libvirt]
   virt_type = qemu    # 注：此配置仅限于Compute节点不支持KVM虚拟化时配置，配置此参数意味着Compute节点将使用纯软件的全虚拟化技术，在性能上远低于KVM虚拟化。启用此参数后就与KVM没有关联了
   ```

4. 在Controller节点上验证nova-compute服务

   ```bash
   [root@controller ~]# source admin-openrc
   [root@controller ~]# openstack compute service list --service nova-compute    # 查看nova-compute服务是否正常
   +----+--------------+---------------------+------+---------+-------+----------------------------+
   | ID | Binary       | Host                | Zone | Status  | State | Updated At                 |
   +----+--------------+---------------------+------+---------+-------+----------------------------+
   |  5 | nova-compute | compute.example.com | nova | enabled | up    | 2025-05-15T15:36:04.000000 |
   +----+--------------+---------------------+------+---------+-------+----------------------------+
   ```

至此，Compute节点的安装已经完成，但还有一个问题，此前理论知识中有提到过，nova-compute服务是需要直接对接Hypervisor的，且nova-compute可以通过不同的Driver来对接不同的Hypervisor，但在Compute节点上修改nova配置文件时却没有调整到有关于Driver的参数选项，这是因为Nova默认就是使用KVM虚拟化，如果要对接其他的虚拟化技术，则必须要具备相应的Driver。例如，nova-compute服务默认情况下不支持esxi，需要对接esxi的话需要单独配置Driver

```bash
vim /etc/nova/nova.conf
[libvirt]
# kvm - <No description provided>
# lxc - <No description provided>
# qemu - <No description provided>
# uml - <No description provided>
# xen - <No description provided>
# parallels - <No description provided>
#virt_type=kvm    # 默认使用KVM虚拟化
```
