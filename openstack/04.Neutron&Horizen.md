# Neutron

OpenStack网络使用的是一个SDN（Software Defined Networking）模块，即Neutron，SDN是一个可插拔的架构，支持插入交换机、防火墙、负载均衡器等，这些都定义在软件中，从而实现对整个云基础设施的精细化管控。组网规划中使用了三个网卡，eth0作为外部网络（在OpenStack术语中，外部网络通常被称为Provider网络），同时也用于管理网络，便于测试访问，生产环境建议分开；eth1用于Cluster Network；eth2用于Tenant网络，即vxlan网络

OpenStack网络部署方式可选的有OVS和LinuxBridge，实验环境中选择LinuxBridge模式，部署过程大同小异。Neutron服务在controller节点和compute节点上都需要安装，同时Neutron与Nova两者服务有交互，所以配置Neutron服务时还需要修改Nova服务的配置

Neutron服务相对于其他OpenStack模块服务，难度更大、更复杂，对于Neutron服务的学习需要从多个不同的维度进行描述

## Neutron架构

![Neutron架构](F:/github/Linux-Server/openstack/image/Neutron架构.png)

Neutron服务内包含了如下组件：

- Neutron Server

  对比其他OpenStack服务，Neutron服务的组件中并没有API组件，Neutron API组件的功能集成在了Neutron Server组件中，Neutron Server组件对外提供Neutron API，接收客户端请求，并调用Plugin处理请求。例如，创建网络、创建子网、创建router等请求。

- Plugin

  Neutron的Plugin按照功能又分为两类：Core Plugin 和 Service Plugin，Core Plugin维护Neutron的network、subnet、port相关资源的信息，Service Plugin提供routing、firewall、load balance等服务。无论是哪一类Plugin，它最终都是用于处理Neutron Server的请求，维护OpenStack的逻辑网络状态，并调用Agent处理请求。

  Plugin维护的是OpenStack的逻辑网络状态，它只负责将创建资源的请求信息写入到数据库并维护数据库中的信息，例如，用户发起请求要创建一个网桥，Plugin从Queue中读取到Neutron Server的请求后，会将网桥的资源信息写入数据库，但Plugin并不会真正在物理节点上创建出这个网桥，而是将Neutron Server请求的资源信息写入数据库后，再通过Queue通知运行在各个物理节点上的Agent，通过对应的Agent创建网桥。

- Agent

  真正用于具体的实现所有的网络细节，处理Plugin的请求，负责在network provider上真正实现各种网络功能。Agent本身也有多种类型，例如，L3 Agent、DHCP Agent、Linux Birdge Agent等类型，当Agent需要在OpenStack网络中实现某一种功能时，需要通过对应类型的Agent实现，例如，在子网内需要实现DHCP功能时，需要通过DHCP Agent实现。

- network provider

  提供网络服务的虚拟或物理网络设备，例如，Linux Bridge、Open vSwitch或其他支持Neutron的物理交换机

- Queue

  Neutron Server、Plugin 和 Agent 之间通过 Messaging Queue 通信和调用。

- Database

  存放OpenStack的网络状态信息，包括Network、Subnet、Port、Router等。

## OpenStack网络类型

在OpenStack官方指南的概述章节中就有提到，OpenStack架构的网络类型分两种：Provider networks 和 Self-service networks

### Provider networks

直译为提供商网络，Provider networks以最简单的方式部署OpenStack Networking服务，主要提供了二层交换网络和VLAN隔离服务。从本质上讲，它将虚拟网络桥接到物理网络，并依靠物理基础设施提供三层路由网络。在Provider networks类型的网络下，用户需要知晓底层网络基础架构的更多信息，以创建与基础架构完全匹配的虚拟网络。

简单一点理解，Provider networks网络类型下，OpenStack只提供单节点下的多实例之间的二层交换网络服务，如果要实现多节点下的多实例之间的二层交换网络、三层路由网络服务，则需要通过网络基础架构来实现，即通过物理交换机、物理路由器设备来实现。因此，Provider networks类型导致OpenStack架构本身缺少对三层专用网络的支持，以及高级服务，例如LBaaS、FWaaS等。

### Self-service networks

Self-service networks选项通过三层路由服务增强了Provider networks选项，这些服务使用叠加分段方法（如VXLAN）启用自助服务网络。实际上，它使用网络地址转换（NAT）将虚拟网络路由到物理网络，此选项还为FWaaS等高级服务提供了基础。OpenStack用户可以创建虚拟网络，而无需了解数据网络上的底层基础架构。如果对二层插件进行了相应的配置，这也可以包括 VLAN 网络。

整个Self-service networks选项，需要详细学习VXLAN网络知识，目前仅需要具备一个基本的认知，将VXLAN理解为类似GRE隧道的概念即可，多个虚拟交换机之间依托于三层路由，通过隧道技术实现不同物理节点上之间的实例的通信。

Self-service networks需要了解三个概念

- Tenant的网络类型

  例如VXLAN、VLAN、FLAT（扁平网络模型，所有实例都属于同一VLAN）

- Router

  租户的实例如果需要连接外网或跨网段通信，则需要通过Router提供的三层网络实现

- Provider

  通过Provider将虚拟网络映射到某个物理网络上

## Neutron配置

在配置Neutron服务之前首先需要明确一点，在此实验的OpenStack规划中，所有服务的API组件所监听的地址都是Manage地址，其次，在Neutron服务上将使用Self-service networks类型的网络，那么Self-service networks至少需要具备两个独立的网络：VXLAN网络、Router网络。VXLAN网络用于实现不同物理节点上、不同实例之间的通信；Router网络用于实现所有实例的外部访问通信。这两个独立的网络都需要单独的网络作为网桥实现，即Provider概念的实现。

### 一、OpenStack网络规划

1. 为所有OpenStack VMware虚拟机节点准备VXLAN网络

   在所有物理节点上都需要一张网卡用于VXLAN网络，VXLAN本质上还是一个隧道网络，因此它也需要一个类似于GRE隧道配置中的隧道源IP、隧道目的IP。VXLAN网络所需要的设备可以直接使用物理网卡，或通过物理网卡新建一个VXLAN网桥，通过VXLAN网桥实现VXLAN隧道网络通信，无论使用哪种方式，VXLAN网络都需要具备一个隧道IP，两种方式本质上都是为了解决VXLAN隧道网络的通信问题

   在基本环境小节中已经配置过VXLAN网卡的IP，所以此处先使用物理网卡的方式进行配置，在尾部补充VXLAN网桥的配置方式

   

   

   ```bash
   # 1.Controller节点新建网桥，用于VXLAN网络
   [root@controller ~]# nmcli connection add type bridge con-name br-trunk ifname br-trunk ipv4.method manual ipv4.addresses 1.1.1.1/24 autoconnect yes
   [root@controller ~]# nmcli connection add type ethernet con-name ens37 ifname ens37 master br-trunk autoconnect yes
   [root@controller ~]# nmcli connection up br-trunk
   [root@controller ~]# nmcli connection up ens37
   [root@controller ~]# nmcli connection delete "Wired connection 1"
   [root@controller ~]# nmcli connection show
   [root@controller ~]# ip add show br-trunk
   
   # 2.Compute节点新建网桥，用于VXLAN网络
   [root@compute ~]# nmcli connection add type bridge con-name br-trunk ifname br-trunk ipv4.method manual ipv4.addresses 1.1.1.2/24 autoconnect yes
   [root@compute ~]# nmcli connection add type ethernet con-name ens37 ifname ens37 master br-trunk autoconnect yes
   [root@compute ~]# nmcli connection up br-trunk
   [root@compute ~]# nmcli connection up ens37
   [root@compute ~]# nmcli connection delete "Wired connection 1"
   [root@compute ~]# nmcli connection show
   [root@compute ~]# ip add show br-trunk
   ```

2. Controller节点需要新建Router网桥

   Router网桥实际是在Neutron服务上构建的，计算节点上不需要Router网桥，计算节点只需要实现二层网络功能，三层网络功能由网络节点（Neutron）实现，但在此实验中将Neutron服务部署在Controller节点上，因此在Controller节点上新建Router网桥。

   以Controller节点上的可以上网的网卡（ens160）作为Router网桥，用于实现实例的外部访问，但需要注意，从最初的配置开始到目前为止，该网卡一直处于在用状态，并且是已具备网络连接的，因此在为该网卡配置新的连接前（bridge-slave），还需要删除该网卡原本在用的网络连接（ens160），需要注意的是，此删除网络连接的操作可能会导致Controller节点断网。

   在本实验中的基本环境配置部分，对于Controller节点的外部网络采用的是静态固定IP，那么在删除原有的ens33网络连接时，系统会自动创建一个"Wired connection 1"绑定到ens33网卡，并自动获取IP，这样子能保障系统的外部网络不会断开，但后续创建新的网络连接绑定到ens33网卡时，仍需要手动删除此"Wired connection 1"网络连接

   ```bash
   [root@controller ~]# nmcli connection delete ens33    # 首先删除原有网络连接，系统会自动新建一个“Wired connection 1”网络连接绑定到ens33网卡
   [root@controller ~]# nmcli connection add type bridge con-name br-ex ifname br-ex ipv4.method manual ipv4.addresses 192.168.31.41/24 ipv4.gateway 192.168.31.1 ipv4.dns 192.168.31.1 autoconnect yes    # 新建用于实现router功能的网桥
   [root@controller ~]# nmcli connection add type bridge-slave con-name bridge-slave ifname ens33 master br-ex autoconnect yes    # 将Controller节点上的可以上网的网卡连接到Router网桥
   [root@controller ~]# nmcli connection up bridge-slave    # 启用bridge-slave网络连接
   [root@controller ~]# nmcli connection delete "Wired connection 1"    # 删除系统自动创建的网络连接
   ```

### 三、安装配置

#### Controller节点配置

安装配置时需要选择对应的网络类型的Neutron安装包，此实验中使用Self-service networks类型

1. 安装Neutron

   ```bash
   [root@controller ~]# yum install -y openstack-neutron openstack-neutron-ml2 openstack-neutron-linuxbridge ebtables
   ```

2. 修改neutron配置文件

   ```bash
   [root@controller ~]# vim /etc/neutron/neutron.conf
   [DEFAULT]
   core_plugin = ml2    # ml2作为Core Plugin，用于实现二层通信
   service_plugins = router    # router是Self-service networks类型必须具备的Service Plugin，实例需要通过router插件实现外部访问
   allow_overlapping_ips = true
   transport_url = rabbit://openstack:openstack_password@controller
   auth_strategy = keystone
   notify_nova_on_port_status_changes = true
   notify_nova_on_port_data_changes = true
   
   [database]
   connection = mysql+pymysql://neutron:openstack_neutron@controller/neutron
   
   [keystone_authtoken]
   www_authenticate_uri = http://controller:5000
   auth_url = http://controller:5000
   memcached_servers = controller:11211
   auth_type = password
   project_domain_name = default
   user_domain_name = default
   project_name = service
   username = neutron
   password = openstack_neutron
   
   [nova]
   auth_url = http://controller:5000
   auth_type = password
   project_domain_name = default
   user_domain_name = default
   region_name = RegionOne
   project_name = service
   username = nova
   password = openstack_nova
   
   [oslo_concurrency]
   lock_path = /var/lib/neutron/tmp
   ```

3. 配置Neutron的Modular Layer 2（ml2）二层插件

   在明确指定`tenant_network_types = vxlan`的情况下，后续就必须配置一个隧道，同时在二层插件里需要定义`mechanism_drivers = linuxbridge`，这个参数意味着OpenStack会自动创建Linux Bridge Agent

   ```bash
   [root@controller ~]# vim /etc/neutron/plugins/ml2/ml2_conf.ini
   [ml2]
   type_drivers = flat,vlan,vxlan    # 类型驱动，代表ml2插件支持什么网络类型
   tenant_network_types = vxlan    # 租户网络类型，明确指明ml2插件支持租户网络类型是vxlan
   mechanism_drivers = linuxbridge,l2population    # 用于指定网络功能的实现方式，例如linuxbridge意味着二层虚拟交换机使用Linux Bridge的方式实现，并且会自动创建Linux Bridge Agent，如果是OVS则生成OVS的Agent
   extension_drivers = port_security    # 支持安全组功能
   
   [ml2_type_flat]
   flat_networks = provider    # 前文提到过通过Provider可以将虚拟网络映射到某个物理网络上，此参数仅定义了flat的网络名称是provider，还没有配置provider所映射的物理网络的具体参数
   
   [ml2_type_vxlan]
   vni_ranges = 1:1000    # 租户网络选择vxlan的前提下，此参数用于设置vxlan的编号范围，vxlan的编号范围可以大于4096
   ```

4. 配置linux bridge agent插件

   ```bash
   [root@controller ~]# vim /etc/neutron/plugins/ml2/linuxbridge_agent.ini
   [linux_bridge]
   physical_interface_mappings = provider:br-ex    # 此参数用于指定在ml2配置文件中定义的flat网络名称（provider），其所对应的外部网络，可以指定物理网卡或网桥
   
   [vxlan]    # 配置隧道端口
   enable_vxlan = true
   local_ip = 1.1.1.1    # br-trunk的IP，指定隧道源IP
   l2_population = true
   
   [securitygroup]    # 启用安全组
   enable_security_group = true
   firewall_driver = neutron.agent.linux.iptables_firewall.IptablesFirewallDriver
   
   [root@controller ~]# vim /etc/sysctl.conf    # 修改内核参数
   net.bridge.bridge-nf-call-iptables = 1
   net.bridge.bridge-nf-call-ip6tables = 1
   [root@controller ~]# modprobe br_netfilter    # 加载内核模块
   [root@controller ~]# sysctl -p    # 加载内核参数
   ```

5. 配置layer-3 agent三层插件

   ```bash
   [root@controller ~]# vim /etc/neutron/l3_agent.ini
   [DEFAULT]
   interface_driver = linuxbridge
   ```

6. 配置DHCP agent插件

   ```bash
   [root@controller ~]# vim /etc/neutron/dhcp_agent.ini
   [DEFAULT]
   interface_driver = linuxbridge
   dhcp_driver = neutron.agent.linux.dhcp.Dnsmasq
   enable_isolated_metadata = true
   ```

7. 配置metadata agent插件

   ```bash
   [root@controller ~]# vim /etc/neutron/metadata_agent.ini
   [DEFAULT]
   nova_metadata_host = controller
   metadata_proxy_shared_secret = openstack_metadata    # 设置元数据共享密码，这个密码会被用在nova服务的配置文件中
   ```

8. 配置nova服务使用neutron服务

   ```bash
   [root@controller ~]# vim /etc/nova/nova.conf
   [neutron]
   auth_url = http://controller:5000
   auth_type = password
   project_domain_name = default
   user_domain_name = default
   region_name = RegionOne
   project_name = service
   username = neutron
   password = openstack_neutron
   service_metadata_proxy = true
   metadata_proxy_shared_secret = openstack_metadata
   ```

9. 完成安装

   Neutron服务初始化脚本需要ML2的配置文件存放在`/etc/neutron/plugin.ini`路径下，可以通过软连接的方式实现

   ```bash
   [root@controller ~]# ln -s /etc/neutron/plugins/ml2/ml2_conf.ini /etc/neutron/plugin.ini
   [root@controller ~]# su -s /bin/sh -c "neutron-db-manage --config-file /etc/neutron/neutron.conf --config-file /etc/neutron/plugins/ml2/ml2_conf.ini upgrade head" neutron    # 填充数据库
   [root@controller ~]# systemctl restart openstack-nova-api    # 重启nova-api组件
   [root@controller ~]# systemctl enable --now neutron-server neutron-linuxbridge-agent neutron-dhcp-agent neutron-metadata-agent    # 启动Neutron服务
   ```

   如果OpenStack架构中使用Self-service Networks选项，则还需要启动layer-3三层服务

   ```bash
   [root@controller ~]# systemctl enable --now neutron-l3-agent
   ```

#### Compute节点配置

在计算节点上只需要配置二层网络即可

1. 安装软件包

   ```bash
   [root@compute ~]# yum install -y openstack-neutron-linuxbridge ebtables ipset
   ```

2. 修改Neutron配置文件

   ```bash
   [root@compute ~]# vim /etc/neutron/neutron.conf
   [DEFAULT]
   transport_url = rabbit://openstack:openstack_password@controller
   auth_strategy = keystone
   
   [keystone_authtoken]
   www_authenticate_uri = http://controller:5000
   auth_url = http://controller:5000
   memcached_servers = controller:11211
   auth_type = password
   project_domain_name = default
   user_domain_name = default
   project_name = service
   username = neutron
   password = openstack_neutron
   
   [oslo_concurrency]
   lock_path = /var/lib/neutron/tmp
   ```

3. 配置linux bridge agent插件

   ```bash
   [root@compute ~]# vim /etc/neutron/plugins/ml2/linuxbridge_agent.ini
   [linux_bridge]
   physical_interface_mappings = provider:br-ex
   
   [vxlan]
   enable_vxlan = true
   local_ip = 1.1.1.2    # br-trunk的IP，指定隧道源IP
   l2_population = true
   
   [securitygroup]
   enable_security_group = true
   firewall_driver = neutron.agent.linux.iptables_firewall.IptablesFirewallDriver
   
   [root@compute ~]# vim /etc/sysctl.conf
   net.bridge.bridge-nf-call-iptables = 1
   net.bridge.bridge-nf-call-ip6tables = 1
   [root@compute ~]# modprobe br_netfilter
   [root@compute ~]# sysctl -p
   ```

4. 修改nova-compute组件配置

   ```bash
   [root@compute ~]# vim /etc/nova/nova.conf
   [neutron]
   auth_url = http://controller:5000
   auth_type = password
   project_domain_name = default
   user_domain_name = default
   region_name = RegionOne
   project_name = service
   username = neutron
   password = openstack_neutron
   ```

5. 完成安装

   ```bash
   [root@compute ~]# systemctl restart openstack-nova-compute
   [root@compute ~]# systemctl enable --now neutron-linuxbridge-agent
   ```

### 四、验证

1. 在Controller节点上检查所有的nova组件状态是否正常

   ```bash
   [root@controller ~]# openstack compute service list
   ```

2. 在Controller节点上检查所有的neutron插件状态是否正常

   ```bash
   [root@controller ~]# openstack network agent list
   ```

   L3 agent提供路由、DHCP agent提供DHCP地址自动分配、metadata agent提供元数据代理，这三个agent插件只会运行在Neutron节点上，在实验规划中运行在Controller节点上

3. 验证vxlan隧道

   仅查看Neutron服务的插件状态是无法直观判断出vxlan网络是否配置正常的，此时可以提前创建一个自定义的网络进行验证vxlan

   ```bash
   [root@controller ~]# openstack network create selfnet    # 创建一个网络，名称为selfnet。创建子网的回显信息中会显示网络类型为vxlan
   [root@controller ~]# openstack subnet create --network selfnet --dns-nameserver 8.8.8.8 --gateway 172.16.1.1 --subnet-range 172.16.1.0/24 selfservice    # 为selfnet网络分配一个子网地址范围，该子网命名为selfservice
   [root@controller ~]# openstack subnet list    # 查看子网列表
   [root@controller ~]# brctl show    # 可以观察到新增了一个网桥，网桥下产生了一个tap接口和vxlan接口
   [root@controller ~]# ip add show    # 观察tap接口的master桥 与 vxlan接口的master桥
   ```


### 五、补充

在配置Neutron服务的物理网卡映射时，不一定必须使用网桥，也可以直接使用物理网卡连接

1. 全节点删除所有网桥

   ```bash
   # 1.Controller节点删除网桥
   [root@controller ~]# openstack network delete selfnet    # 删除selfnet网络，删除openstack网络时可以通过指定ID或Name删除指定网络
   [root@controller ~]# nmcli connection delete br-trunk    # 删除用于vxlan网络的网桥
   [root@controller ~]# nmcli connection delete br-ex       # 删除用于router三层网络服务的网桥
   [root@controller ~]# nmcli connection delete bridge-slave    # 删除物理机用于连接到router三层网络服务的物理网卡连接
   [root@controller ~]# nmcli connection delete ens37       # 删除物理机用于连接到vxlan网络的物理网卡连接
   [root@controller ~]# nmcli connection show
   
   # 2.Compute节点删除网桥
   [root@compute ~]# nmcli connection delete br-trunk
   [root@compute ~]# nmcli connection delete ens37
   [root@compute ~]# nmcli connection show
   ```

2. 全节点重建网卡连接

   ```bash
   # 1.Controller节点重建网卡连接
   [root@controller ~]# nmcli connection add type ethernet con-name ens33 ifname ens33 ipv4.method manual ipv4.addresses 192.168.31.40/24 ipv4.gateway 192.168.31.1 ipv4.dns 192.168.31.1 autoconnect yes
   [root@controller ~]# nmcli connection up ens33    # 重建外部网络连接
   [root@controller ~]# nmcli connection add type ethernet con-name ens37 ifname ens37 ipv4.method manual ipv4.address 1.1.1.1/24 autoconnect yes
   [root@controller ~]# nmcli connection up ens37    # 重建vxlan网络连接
   
   # 1.Compute节点重建网卡连接
   [root@compute ~]# nmcli connection add type ethernet con-name ens37 ifname ens37 ipv4.method manual ipv4.addresses 1.1.1.2/24 autoconnect yes
   [root@compute ~]# nmcli connection up ens37    # 重建vxlan网络连接
   ```

3. 在全节点上配置linux bridge agent插件

   ```bash
   # 1.Controller修改linuxbridge插件的配置
   [root@controller ~]# vim /etc/neutron/plugins/ml2/linuxbridge_agent.ini
   [linux_bridge]
   physical_interface_mappings = provider:ens33
   
   # 1.Compute修改linuxbridge插件的配置
   [root@compute ~]# vim /etc/neutron/plugins/ml2/linuxbridge_agent.ini
   [linux_bridge]
   physical_interface_mappings = provider:ens33
   ```

4. 重启网络服务或重启机器即可



















# Horizen

Horizon服务唯一需要的核心服务是Keystone服务，Horizon服务可以与OpenStack其他服务结合使用，例如Glance服务、Nova服务，还可以在具有独立服务（如Object Storage）的环境中使用Horizon服务。在部署Horizon服务之前，需要确保环境中已存在配置、运行了HTTP组件和Memcached组件的Keystone服务。

## Dashboard配置

### 一、Dashboard安装

1. 安装软件包

   ```bash
   [root@controller ~]# yum install -y openstack-dashboard
   ```

2. 修改Horizon配置文件

   ```bash
   [root@controller ~]# vim /etc/openstack-dashboard/local_settings
   OPENSTACK_HOST = "controller"
   OPENSTACK_KEYSTONE_URL = "http://%s:5000/v3" % OPENSTACK_HOST    # 在配置了OPENSTACK_HOST选项后，此选项使用默认参数即可
   ALLOWED_HOSTS = ['*']    # *号表示允许所有主机访问
   SESSION_ENGINE = 'django.contrib.sessions.backends.cache'
   
   CACHES = {
   	'default': {
   		'BACKEND': 'django.core.cache.backends.memcached.MemcachedCache',
   		'LOCATION': 'controller:11211',
   	}
   }
   OPENSTACK_KEYSTONE_MULTIDOMAIN_SUPPORT = True    # 此选项用于支持多Domain管理
   OPENSTACK_API_VERSIONS = {    # API接口版本
   	"identity": 3,
   	"image": 2,
   	"volume": 3,
   }
   OPENSTACK_KEYSTONE_DEFAULT_DOMAIN = "Default"    # 默认的Domain
   OPENSTACK_KEYSTONE_DEFAULT_ROLE = "user"
   TIME_ZONE = 'Asia/Shanghai'
   ```

   如果OpenStack架构规划中使用的网络类型是Provider networks类型，则还需要在Horizon配置文件中添加以下配置

   ```bash
   OPENSTACK_NEUTRON_NETWORK = {
   	'enable_router': False,
   	'enable_quotas': False,
   	'enable_distributed_router': False,
   	'enable_ha_router': False,
   	'enable_lb': False,
   	'enable_firewall': False,
   	'enable_vpn': False,
   	'enable_fip_topology_check': False,
   }
   ```

3. 修改httpd配置文件

   ```bash
   [root@controller ~]# vim /etc/httpd/conf.d/openstack-dashboard.conf
   ServerAdmin root@controller.example.com
   ServerName  controller.example.com
   
   WSGIApplicationGroup %{GLOBAL}
   ```

   在安装openstack-dashboard软件包后会自动在`/etc/httpd/conf.d`路径下生成Dashboard的httpd配置文件，OpenStack官方指南建议在这个原始的httpd配置文件中修改、添加配置，修改原始httpd配置文件完成后访问`http://controller/dashboard/`验证Dashboard服务。但这种方式可能会产生身份验证的问题，如果出现身份验证问题，建议采用下面这种方式重新生成Dashboard的配置文件并进行修改

   ```bash
   [root@controller ~]# python /usr/share/openstack-dashboard/manage.py make_web_conf --apache > /etc/httpd/conf.d/openstack-dashboard.conf    # 生成Dashboard的httpd服务的配置文件
   [root@controller ~]# vim /etc/httpd/conf.d/openstack-dashboard.conf
   ServerAdmin root@controller.example.com
   ServerName  controller.example.com
   
   WSGIApplicationGroup %{GLOBAL}    # 重新生成的Dashboard配置文件里已经自带有此参数，无需手动添加
   ```

4. 重启httpd服务

   ```bash
   [root@controller ~]# systemctl restart httpd memcached
   ```
