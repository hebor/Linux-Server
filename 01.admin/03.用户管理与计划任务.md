# 用户管理

Linux安全系统的核心是用户账户，系统中各种资源对象的访问权限也取决于登录系统时所使用的的账户，创建账户时会为每个账户分配一个唯一的UID，Linux系统会根据UID来跟踪对应的账户权限；Linux系统会为各种服务创建不同的账户，这些账户叫做*系统账户*，它们并不是真正的用户，是系统上运行的各种服务进程访问系统资源需要用到的特殊账户

- 超级管理员账户

  账户名称是root，uid永远是0

- 系统账户

  用于管理进程信息，一般不允许系统账户直接登录系统；Centos6中系统账户uid范围是1\~499，Centos7的系统账户uid范围是1\~999

- 普通用户

  相比较root用户，普通用户在系统权限上受到限制。根据`/etc/login.defs`配置文件中的`UID_MIN、UID_MAX`默认参数，普通用户的UID从1000开始编号，默认最大为60000，但UID的取值范围并不是只到60000

著名的傀儡用户nobody，部分没有专门的虚拟用户管理的某些服务，又不想用root用户进行管理时，就会用到nobody账户。在CentOS 7上nobody是uid为99的特殊用户，Ubuntu系统将nobody用户的uid设置为65534，RHEL的新版本系统中也将nobody账户的uid设置为65534

## 用户组

用户组的作用是为了方便管理用户，Linux系统上许多权限限制可以针对用户组来设置，属于该用户组下的所有用户会享有用户组的权限，与用户账户UID类似，用户组也具备一个唯一标识GID，GID编号默认情况下也是从0开始编号，最大60000

Linux系统下每一个用户必须至少属于一个组，组名可以与用户名完全相同，一个用户也可以属于多个组。基于这种情况下，用户组由分为两类：基本组和附加组（从属组），在Linux系统上创建普通用户时，会同步创建与用户同名的用户组，并将用户与用户组绑定，这就是基本组；附加组由管理员单独创建，且由管理员将用户与附加组进行绑定

## 用户信息

- `/etc/passwd`：保存用户相关信息
- `/etc/shadow`：用户密码信息
- `/etc/group`：保存用户组相关信息
- `/etc/gshadow`：保存用户组相关信息

```shell
[root@localhost ~]# cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
# 用户名:密码占位符:UID:基本组GID:账户描述:用户家目录:用户Shell程序的路径

[root@localhost ~]# cat /etc/shadow
hebor:$6$3zsTNd1e$h0XujmiKglxMy2fa72s4mcNoL.Bsgh63PaLnzcBOIm1BtVxqU4NihlgbxADADbdEZbRHmK8zb68P/2Mgc1MmR0:20252:0:99999:7:::
# 用户名:加密密码:自1970-1-1到上一次修改密码的间隔时间（天数）:密码最短修改间隔（至少需要使用N天以后才能修改）:密码最长修改时限:密码过期提醒时间（提前7天提醒密码即将过期）:密码过期宽限时间:账号失效时间:保留
```

在早期的Linux上，/etc/passwd文件中有加密后的用户密码，但鉴于很多程序都需要访问/etc/passwd文件获取用户信息，这成为了一个安全隐患，现在绝大多数Linux系统都将用户密码单独存放在/etc/shadow文件中，只有特定程序才能访问这个文件，而/etc/passwd文件中的密码栏则改为了密码占位符`x`

## 用户家目录信息

`/etc/skel`目录特征

1. 此目录下的文件都是隐藏文件
2. 此目录能够协助修复被破坏的家目录

`/etc/skel`目录文件解析

- `.bash_profile`：用于定义环境变量，每次登录系统时执行
- `.bashrc`：此文件被用于永久保存用户独有的别名信息，这个文件最主要的特征是**每新建一个Bash环境时都会执行一次此文件的内容**（开启新的终端或新的SSH连接）
- `.bash_logout`：执行退出指令时，同时执行此文件内的命令信息。`logout`命令也可用于退出

除了`/etc/skel`目录下的三个文件以外，还有一个文件比较重要，存放在用户家目录下的`.bash_history`文件，此文件用于记录用户执行过的历史命令信息，但该文件并不会实时保存历史命令信息，最新的历史命令信息保存在内存中，`.bash_history`文件会定时读取内存中的命令信息并写入。`history -w`命令手动写入

`/etc/skel/`目录下保存了用户的初始环境变量文件。例如使用`useradd hebor`命令时，大致分为3个步骤

1. 创建用户并将用户信息写入/etc/passwd文件
2. 创建用户家目录，并通过`cp /etc/skel/* /home/hebor/`将sekl目录下的所有文件拷贝到新用户的家目录下
3. 修改用户家目录的数据权限信息，即`chown -r hebor.hebor /home/hebor/`

对以上步骤可以做个验证，在`/etc/skel/`目录下随意创建一个文本文件，然后新建一个用户，此刻新建的用户家目录下就存在新建的文本文件

```shell
# 1. 使用普通用户删除家目录下的所有数据
[hebor@localhost ~]$ rm -rf ~/*
# 2. 重新登录该普通用户就会发现用户提示符出现异常，此时再用root用户删除普通用户的家目录，并复制/etc/skel/目录重命名为普通用户的家目录，直接cp /etc/skel/*目录下的文件可能会不生效
[root@localhost ~]# \rm -r /home/hebor/
[root@localhost ~]# echo 123 > /etc/skel/hebor.txt    # 新建测试文本文件
[root@localhost ~]# cp -a /etc/skel/ /home/hebor/
[root@localhost ~]# chown -R hebor.hebor /home/hebor/    # 修改用户家目录权限
# 3. 验证普通用户的提示符是否已正常，检查用户家目录下是否存在新建文件
```

## 用户管理命令

1. 创建用户

   ```bash
   [root@localhost ~]# useradd hebor
   	-u：指定UID
   	-d：指定用户家目录，默认在家目录路径是/home/用户名
   	-G：指定附加组
   	-s：指定用户shell，默认使用/bin/bash
   	-p：设置用户密码
   [root@localhost ~]# id hebor    # 查看用户的基本信息
   ```

   使用`-d`选项创建家目录时，需要确保路径下不存在与家目录同名的目录，否则无法正常将`/etc/skel`目录下的初始环境变量文件复制到用户家目录下。需要注意的是，这个问题并不会影响用户的正常创建，但会影响到用户的登录，用户登录时会产生异常

   useradd作为Linux系统用于添加新用户的主要工具，它使用系统的默认值和命令行参数来设置新账户属性信息，系统默认值被设置在/etc/defaut/useradd文件中，也可以通过`useradd -D`选项查看默认值；使用不同Linux发行版创建新用户时应先查看useradd的默认值，因为不同发行版的默认值不同，创建出来的新用户属性信息可能不符合管理员预期
   
   ```bash
   GROUP=100   新用户会被添加到GID为100的公共组
   HOME=/home  新用户的HOME将会位于/home/loginname
   INACTIVE=-1 新用户账户密码过期后不会被禁用
   EXPIRE= 新用户账户不设置过期日期
   SHELL=/bin/sh   新用户账户使用sh作为默认shell
   SKEL=/etc/skel  将此目录下内容复制到新用户的HOME目录下
   CREATE_MAIL_SPOOL=no    不为新用户创建用于接收邮件的文件
   ```

2. 创建组

   ```bash
   [root@localhost skel]# groupadd tmooc    # 创建用户组
   [root@localhost skel]# useradd -G tmooc test01
   [root@localhost skel]# id test01         # 查看用户附加组
   ```

3. 修改用户属性

   修改用户属性的前提是用户账户在系统上必须已存在

   ```bash
   [root@localhost skel]# usermod -l test02 test01
   	-l：修改用户的账户名
   	-u：修改用户UID
   	-d：修改用户家目录，此选项仅修改/etc/passwd文件中的用户属性信息，但不会自动创建新的用户家目录
   	-s：修改用户shell
   	-G：定义用户附加组，此选项会重置用户所有的附加组，而不是基于原有附加组的基础上新增附加组
   ```

4. 账户密码

   默认情况下创建的新账户是没有密码的，没有密码的账户不允许登录

   ```bash
   # 修改用户密码：passwd
   [root@localhost ~]# passwd hebor    # 交互式修改用户密码，普通用户只允许直接使用passwd命令修改自身密码
   [root@localhost ~]# echo redhat | passwd --stdin hebor    # 非交互式修改用户密码
   
   # 修改用户密码：chpasswd
   [root@localhost ~]# echo hebor:redhat | chpasswd    # 非交互式修改用户密码
   [root@localhost ~]# chpasswd < passwd.txt           # 从文件批量修改用户密码，文件内容书写格式为Username:Password
   
   # CLI切换账户：su
   [root@localhost ~]# su hebor
   [hebor@localhost root]$ exit
   [root@localhost ~]# su - hebor
   [hebor@localhost ~]$ exit
   ```
   
   命令行切换账户时，使用`su`或`su -`都可以成功切换账户，两者的差异在于环境变量，`su`命令直接使用只会对部分环境变量有影响，`su -`命令会完全切换到目标用户的环境变量。当用户shell为`/sbin/nologin`时，即便是root账户也无法使用su切换到该用户
   
5. 删除用户

   用户处于登录状态时不可被删除

   ```bash
   [root@localhost ~]# userdel -r test02
   	-r：连同用户家目录、用户邮箱一并删除
   ```

   在执行删除用户操作时需要注意，为了避免造成数据丢失，尽量不要删除用户，而是注释用户。默认情况下userdel命令只会删除用户信息，即`/etc/passwd`等文件中所记录的用户信息，但不会删除用户的家目录，这可能会导致下次创建同名用户时，因用户家目录名称冲突导致创建用户异常。在创建新用户时使用`-g`参数，或先手动删除残留的用户家目录都可以解决这个问题

   某些场景下在创建用户时就没有创建该用户的家目录，使用`userdel -r`删除此类用户时会提示找不到用户家目录的报错，但此时用户信息仍已经被成功删除了

6. 用户组命令

   ```bash
   # 创建组
   [root@localhost ~]# groupadd test01
   
   # 管理组
   [root@localhost ~]# gpasswd -a hebor test01
   [root@localhost ~]# gpasswd -M 'root,hebor' test01
   	-a：添加组成员，每次只能添加一个
   	-d：删除组成员，每次只能删除一个
   	-M：定义组成员用户列表，批量定义组成员，使用此参数会覆盖掉原有的组成员列表
   	-A：定义组管理员列表，与-M参数类似，也可以批量定义组管理员
   	
   # 删除组
   [root@localhost ~]# groupdel tmooc    # 基本组不可删除
   
   # 组账号文件
   [root@localhost ~]# cat /etc/group
   hebor:x:1000:
   #组名:密码占位符:GID:本组的成员用户列表
   [root@localhost ~]# cat /etc/gshadow
   test01:!:hebor:root,hebor
   #组名::加密密码（!号表示组未设置密码）:组管理员:本组的成员用户列表
   ```
   
   默认情况下在Linux系统中，只有root用户可以管理组成员，通过`gpasswd -A`将普通用户定义为某一个组的组管理员，使普通用户可以管理组成员，实现有限权限的下放。组管理员的权限依旧是比较有限的，组管理员可以通过添加、删除组成员来实现与`gpasswd -M`相同的效果，但组管理员仍没有权限直接使用gpasswd的`-M`、`-A`选项

### sudo

sudo命令的本质是权限的变更，它用于以其他人的身份执行命令，预设的身份为root。在/etc/sudoers中设置了可执行sudo指令的用户。若其未经授权的用户企图使用sudo，则会发出警告的邮件给管理员。用户使用sudo时，必须先输入密码，之后有5分钟的有效期限，超过期限则必须重新输入密码。sudo权限配置格式：

```shell
root    ALL=(ALL)       ALL

# 源用户  可执行命令的主机=(目标权限用户)  可执行命令
hebor  ALL=(root)  /usr/bin/more /etc/shadow,/usr/bin/more /etc/gshadow

# 上述语法在最大程度上限制了普通用户的权限只能操作某些文件，另一种方式是直接将某些命令的权限给到普通用户
hebor   ALL=(root)      /usr/bin/more,/usr/bin/echo

# 涉及到比较多的命令权限的问题时，可使用通配符，表示将目标目录下的所有可执行命令的权限给到普通用户
hebor   ALL=(root)      /usr/bin/*

# 由于通配符的权限过大，为了限制普通用户的权限，排除部分命令的权限不给于普通用户
hebor   ALL=(root)      /usr/bin/*,!/usr/bin/vim

# 免密码执行sudo，在可执行命令区域的最前面加上NOPASSWD:
hebor   ALL=(root)      NOPASSWD: /usr/bin/more,/usr/bin/echo

# 用户hebor在主机master上，可以以用户alex或jerry的身份执行kill命令
hebor   master=(alex,jerry)    /bin/kill
```

一些比较特殊的系统服务用户，其“可执行命令的主机”和“可执行命令”一般都是ALL，当“可执行命令的主机”指定为具体的主机名时，源用户只能在该主机上具备有限的权限；当“目标权限用户”有多个时，可以通过`sudo -u`明确以某一个目标用户的身份执行命令，或直接在`/etc/sudoers`配置文件中申明默认以某个目标用户的权限执行命令



Linux系统建议使用visudo命令来配置用户的sudo权限，但实际上visudo命令本质上就是修改`/etc/sudoers`文件，通过vim直接编辑`/etc/sudoers`文件也可以实现与visudo命令同样的效果，建议使用visudo命令是因为此命令具备语法自动检查功能，配置编辑有误时visudo命令会有直观的提示。然而，手动编辑`/etc/sudoers`文件后也可以通过`visudo -c`手动检查`/etc/sudoers`文件的语法是否正确

`/etc/sudoers`配置文件的编写需要注意“可执行命令”的语法编写格式，“可执行命令”必须使用命令的绝对路径，且不能使用井号注释符；需要授权多个权限命令的情况下，用逗号或空格进行分隔。当”目标权限用户“不是root时，对于Linux系统中默认存在的一些重要配置文件，即便sudo变更到其他普通用户仍然无法进行授权操作，如果一定要使普通用户能够修改文件，那么只能修改文件本身的权限。例如`/etc/hosts`文件本身就属于普通用户无权操作的类型，因此即便源用户hebor使用sudo变更权限为alex，仍无权对`/etc/hosts`文件进行操作

```shell
hebor   ALL=(alex)      /usr/bin/more /etc/shadow,/usr/bin/more /etc/gshadow,/usr/bin/echo 123 >> /etc/hosts
```

修改visudo的默认编辑器，修改默认编辑器之前需要先确保vim已经安装完成

```shell
vim /etc/sudoers
Defaults    editor=/usr/bin/vim    # 添加此行，vim的实际路径可以通过which命令检索
```

#### sudo日志

sudo日志默认不开启，需要修改`/etc/sudoers`配置文件手动开启日志，开启日志后可以通过`sudo -`切换到普通用户后执行一下`sudo`命令，再查看`sudo`日志文件是否存在记录

```shell
[root@master ~]# touch /var/log/sudo.log
[root@master ~]# visudo
...
Defaults    logfile=/var/log/sudo.log
...
```

>  **`su` 和 `sudo` 的区别**

su 命令直接切换到目标用户，sudo 命令只是临时执行目标用户权限的部分命令

# 定时任务

定时任务通常被用于按照设定的时间为用户执行某些固定的系统任务，定时任务又被分为一次性定时任务和周期性定时任务，两者软件包和工具各不相同，定时任务的重点会放在周期性定时任务上

cronie是CentOS 7系统默认的定时任务工具，也是周期性定时任务工具，与其相关的还有客户端执行程序crontab、系统守护进程crond、日志文件`/var/log/cron`；at是CentOS 7系统下的一次性定时任务工具，需要单独安装at软件包并启动atd服务，与其相关的包括客户端执行程序at、系统守护进程atd、日志文件`/var/log/cron`，atd的日志与crond的日志保存在同一文件中

## 定时任务命令解析

1. 管理定时任务

   ```bash
   # 周期性定时任务
   [root@localhost ~]# crontab -e -u hebor
   	-e：编辑定时任务
   	-l：查看定时任务
   	-r：删除用户的所有定时任务
   	-u <user>：指定执行该定时任务的用户身份，不指定定时任务的用户时，默认为当前用户创建定时任务
       -i：执行命令前提示
       -x <mask>：启动调试模式
   
   # 一次性定时任务
   [root@localhost ~]# echo "hello world" | at 14:55    # 非交互式编写定时任务
   [root@localhost ~]# at -l    # 查看任务列表
   	-l：查看任务列表，atq命令可以实现同样的效果
   	-c 2：查看ID为2的任务详情
   	-d 2：删除ID为2的任务，atrm可以实现同样的效果
   ```

   配置crontab定时任务后，在`/var/spool/cron/`目录下会自动创建对应用户名文件

2. crontab基本语法格式

   使用crontab编辑定时任务时实际上就是通过文本编辑器编写执行的时间与执行的指令，crontab周期性定时任务的语法格式可以参照`/etc/crontab`文件

   ```bash
    分    时     日    月     周      任务命令行（绝对路径）
   0~59  0~23  1~31  1~12   0~7     0或7都代表星期日
   
   * * * * *       #每分钟执行一次
   30 8 * * *      #每天8点30执行一次
   * 8 * * *       #每天8点开始执行，每分钟执行一次，总共执行60次，直到9点不再执行
   30 23 * * 5     #每周五23点30执行一次
   30 23 * * 1-5   #每周的周一到周五的23点30执行一次
   30 23 * * 1,3,6 #每周的周一、周三、周六的23点30执行一次
   30 23 1 * 1     #每月的1号或每周一的23点30执行一次
   */5 * * * *     #每隔5分钟执行一次
   1 */2 * * *     #每隔2小时执行一次，如果将分钟改为*，则匹配一小时内的60分钟，实现的效果就是每个2小时执行60次
   ```

   crontab语法格式中对于执行时间的编写有4种方式：

   - *：匹配范围内的任意时间
   - ,：分割多个不连续的时间点
   - -：指定连续时间范围
   - /n：指定时间频率。例如，每n小时执行一次

   编写定时任务时建议使用crontab命令编辑，crontab可以自动检测配置文件的语法，也可以直接在`/var/spool/cron/`目录下创建对应用户名的配置文件，直接编辑配置文件实现定时任务。虽然两种方式最终实现的效果是一样的，但后者不仅没有语法检测，并且cron日志中也不会记录该配置文件的创建和编辑过程

   每次创建定时任务后都需要检测定时任务是否生效，一般可以通过临时修改系统时间对定时任务进行测试，如果定时任务未生效，则需要查看定时任务日志进行检查。需要注意的是，计划任务会在内存中执行，它不会将执行结果直接输出到命令行，执行结果会输出到后台，会通过日志体现执行过程。例如，定时任务使用echo输出文本信息，不会直接在命令行输出信息

3. 定时任务示例

   ```bash
   # 每分钟记录当前系统时间，写入/opt/time.txt
   [root@localhost ~]# crontab -e
   * * * * * /usr/bin/date >> /opt/time.txt
   [root@localhost ~]# crontab -l
   [root@localhost ~]# cat /opt/time.txt    # 检查文件内容
   [root@localhost ~]# crontab -r    
   ```

   使用`crontab -r`会清空当前用户的所有定时任务，如果需要单独删除某一条定时任务，仍使用`crontab -e`选项编辑即可，删除不需要的某一条定时任务

## 系统定时任务

通过crontab编辑的定时任务都是针对用户的定时任务，即便不使用`crontab -u`指定用户，它默认为当前用户创建定时任务。cronie作为CentOS 7系统默认的定时任务工具，它在CentOS 7系统上具备4个固定执行时间的目录，将脚本文件直接放置在这些目录下即可周期性执行：

- 任务周期：每小时 `/etc/cron.hourly/`
- 任务周期：每天 `/etc/cron.daily/`
- 任务周期：每周 `/etc/cron.weekly/`
- 任务周期：每月 `/etc/cron.monthly/`

除了以上四个固定执行周期的定时任务目录，无论是at或cronie都具备其独立的权限控制配置文件，用于管控是否允许普通用户具备设置其定时任务的权限：

- `/etc/cron.allow`：crontab白名单文件，默认不存在，用于允许指定用户可以使用crontab设置定时任务
- `/etc/cron.deny`：crontab黑名单文件，阻止指定用户不能使用crontab设置定时任务
- `/etc/at.allow`：at白名单文件，默认不存在，用于允许指定用户可以使用at设置定时任务
- `/etc/at.deny`：at黑名单文件，用于阻止指定用户不能使用at设置定时任务

需要注意的是，at和cronie的白名单文件权限优于黑名单文件，如果使用白名单文件可能会导致系统中大部分普通用户都失去配置定时任务的权限，系统默认未创建白名单文件。除了以上四个权限文件以外，还需要注意`/etc/crontab`文件，它是crontab定时任务的参考说明文件，不要在此文件下直接编辑定时任务

日志文件切割处理`logrotate`任务是系统默认设置好的定时任务

```shell
vim /etc/logrotate.conf
# rotate log files weekly    # 每周切割保存一次日志
weekly


# keep 4 weeks worth of backlogs    # 仅保留最近4周的日志数据
rotate 4


# create new (empty) log files after rotating old ones    # 旧日志数据切割保存后创建新的空日志文件
create


# use date as a suffix of the rotated file    # 文件保存的命名以日期结尾
dateext


# uncomment this if you want your log files compressed    # 压缩日志数据文件
#compress
# delaycompress     # 总是与 compress 选项一起用，delaycompress 选项指示 logrotate 不要将最近的归档压缩，压缩将在下一次轮循周期进行。这在你或任何软件仍然需要读取最新归档时很有用。

    rotate 1

```

##  定时任务编写技巧

定时任务配置文件中的符号信息

- *：每次    每分钟/每小时/每天/每月/每周
- */n：时间间隔    每隔n分钟/每隔n小时/每隔n天/每隔n月
- n-m：连续时间范围    n到m分钟/n到m小时...
- n,m：不连续的时间范围    n分钟和m分钟/n小时与m小时...

有时可能会看到 `m/n * * * *` 这样的写法，这表示到m分钟的前n分钟执行操作，例如 `30/10 * * * *` 表示`1:30`的前10分钟执行操作，小时位是循环的，可以是`2:30`、`3:30`等

编写定时任务时，上一级时间有设置时，尽量对下级时间也要设置，例如每天中午12点应该写成 `00 12 * * *` ，即便没有对分钟有具体声明，也应该对其有具体设置，如果分钟位不进行设置，也就是`*`分，这代表每天中午12点的每分钟都会执行一次动作，直到13点结束执行，中间会执行60次操作

定时任务的注意事项

1. 在定时任务中不能识别一些特殊的符号信息。例如`` ` ``号、`.`号等 -- 使用脚本执行定时任务
2. 无论是文件名或是命令，编写定时任务时要使用绝对路径 -- 定时任务能识别的环境变量`$PATH=/usr/bin:/bin`
3. 每个定时任务都需要注释说明
4. 当操作的命令超过2个时，尽量使用脚本文件
5. 每个定时任务的结尾使用错误重定向将错误输出内容重定向到/dev/null，避免磁盘空间被占用
6. 在定时任务中，执行命令尽量不要产生输出信息 -- 正常的警告或提示信息输出仍会产生邮件提示，例如使用tar命令时，省略-v选项，尽量使用相对路径压缩


错误示范

```shell
# 特殊符号不识别
00 12 * * * cp /etc/hosts >> /tmp/backup/hosts_$(date +%F).txt

# 脚本文件未使用绝对路径
00 12 * * * bash ./test.sh

# 定时任务环境变量不同导致命令执行有问题
00 12 * * * ip address show eth0 > /tmp/backup/hosts_

00 12 * * * echo $PATH > /tmp/backup/hosts
```

执行定时任务时可能会收到邮件`You have mail in /var/spool/mail/root`，这个邮件是由postfix服务产生的，**定时任务执行出错时**就会产生错误邮件

如果不想显示收到邮件的提示可以选择关闭postfix服务，但关闭postfix服务后仍然会产生邮件，这时产生的邮件会暂时保存到`/var/spool/postfix/maildrop/`目录中，此目录下可能会产生大量小文件，占用过多的inode。重启postfix服务时会将`/var/spool/postfix/maildrop/`目录的文件处理掉
