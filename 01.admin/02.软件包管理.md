# 软件包管理

Linux系统的软件包都存放在ISO镜像中，管理员要执行软件包管理操作时，大多数时候可以使用本地ISO镜像中的软件包，或第三方单位在互联网上公开的软件包，使用本地ISO镜像中的软件包时需要先挂载镜像，使用本地ISO镜像时需要确保镜像版本与操作系统版本相对应，最好直接挂载安装系统时使用的ISO镜像  

```bash
[root@localhost ~]# mkdir /mnt/iso
[root@localhost ~]# mount /dev/sr0 /mnt/iso
```

Linux系统常见的软件封包类型

| 封包类型     | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| RPM软件包    | 扩展名一般以.rpm结尾，适用于RedHat系列                       |
| deb软件包    | 扩展名一般以.deb结尾，适用于Debian系列                       |
| 源代码软件包 | 通常以.tar.gz、tar.bz2格式的压缩包提供，包含程序的原始代码文件 |
| 其他         | 提供install.sh、setup、\*.bin、\*.pl等安装文件，或绿色免安装、已经编译好的程序 |

在Linux系统下有4种软件安装方式：yum安装、rpm安装、编译安装、二进制包安装

## RPM软件包管理

RPM（RedHat Package Manager）由RedHat公司提出，RedHat、SUSE等发行包通用。Linux系统上的软件包状态信息会自动的集中记录到软件包的数据库中，这个数据库由Linux系统自动维护，用于记录软件包安装、卸载、版本等变化信息，分析软件包依赖关系。RPM软件包的包名一般都比较长，这是为了使管理员能够得到更多的信息，以`firefox-52.7.0-1.el7.centos.x86_64.rpm`包名为例，其每个字段分别代表着`软件名-版本信息.操作系统.硬件架构.rpm`

相比较Windows的软件安装，RPM包的安装过程没有所谓“下一步”的提示、不允许用户自定义安装路径、不允许用户自定义安装的功能，RPM包的安装路径、安装功能在软件包内直接写为固定参数，回车即代表着软件包的安装。虽然RPM包不允许选择安装路径与功能，但它同样也存在一些常见的安装路径

| 文件类别             | 默认安装位置                     |
| -------------------- | -------------------------------- |
| 普通可执行程序       | /usr/bin/、/bin/                 |
| 服务器程序、管理工具 | /usr/sbin/、/sbin/               |
| 日志文件             | /var/log/、/var/log/软件名/      |
| 程序文档、man手册页  | /usr/share/doc/、/usr/share/man/ |

### RPM指令解析

```bash
# 查询操作；单纯的使用-q选项的组合，查询的都是已安装的软件包信息，结合-p选项后可以查询未安装的软件包信息
[root@localhost ~]# rpm -q openssh-server
	-q：查询指定软件包是否已安装
	-a：显示所有软件包
	-l：显示软件包的文件列表
	-c：仅显示组态配置文件
	-f：显示文件或命令属于哪个软件包
	-p：显示指定的软件包信息
[root@localhost ~]# rpm -qa    # 查询系统已安装的所有软件包列表
[root@localhost ~]# rpm -qi openssh-server    # 查询软件的详细信息
[root@localhost ~]# rpm -ql openssh-server    # 查询软件各文件的安装路径
[root@localhost ~]# rpm -qc openssh-server    # 查看软件包配置文件的安装路径
[root@localhost ~]# rpm -qf /etc/hostname     # 根据文件名逆向查询该文件属于哪个软件包，需要输入文件路径
[root@localhost ~]# rpm -qpi /mnt/iso/Packages/vsftpd-3.0.2-28.el7.x86_64.rpm    # 使用p选项时必须指定完整的软件包名称
[root@localhost ~]# rpm -qpl /mnt/iso/Packages/vsftpd-3.0.2-28.el7.x86_64.rpm    # 可以查到该软件的预安装路径

# 安装软件包
rpm -ivh PackageName
	-i：安装软件包；安装的软件包存在其他依赖关系时，RPM安装软件会失败
	-v：显示详细信息
	-h：显示进度条
	-U：升级软件包
	--force：强制覆盖安装
	--test：测试安装，不做真实安装动作
rpm -Uvh PackageName    # 更新安装包

# 卸载软件包
rpm -e PackageName
	-e：卸载软件包
```

基于RPM软件包的数据库机制，`rpm -qf`查询的文件即便在Linux系统上删除了该文件，大多数情况下也是能够查询到该文件所属的软件包信息的，当文件在Linux系统上被删除后，RPM仍能够查询数据库中的记录，但这种方式并不是绝对通用的

#### 软件包警告信息

在使用RPM查询软件包的详细信息时会产生一个警告，这个警告本身对软件包没有任何的影响，大多数情况下可以不必理会此告警。产生此告警的原因是出于系统软件的安全性考虑，早期由于Linux平台的开源，黑客会将恶意代码写入软件的源代码中，导致系统安装该软件时就会被劫持。为了避免这种情况，Linus联合RedHat将市面上常用的开源软件全部进行了一遍检测，确保软件正常后RedHat会在软件包内做一个签名信息

软件包的详细信息中产生的NOKEY告警，代表着Linux系统在该软件包中没有发现RedHat的签名信息。但实验环境中实际上是有RedHat签名的，因为软件包来自ISO镜像，而ISO镜像又是由RedHat全球发布的，此处产生NOKEY告警的原因是因为系统不识别RedHat的签名信息，导致系统认为软件包没有签名。RedHat的签名信息存放在ISO镜像的`/mnt/iso/RPM-GPG-KEY-CentOS-7`路径下，只需要手动导入RedHat的签名信息即可解决此告警，由于该告警并不会影响到软件包的正常使用，一般情况下单独去导入RedHat的签名信息

## YUM软件包管理

依赖关系是在Linux系统上安装软件无法避免的一个问题。例如，安装A软件包时，A软件包需要B软件包中提供的运行环境，那么此时就需要先安装B软件包，再回头安装A软件包，这就是软件包之间的依赖关系。Linux系统发展至今，各个软件包之间存在非常复杂的依赖关系，要安装一个软件包，可能会牵扯到非常多的依赖包，通过人工解决这个问题已经变得异常困难，于是YUM产生了

YUM是基于RPM包构建的软件更新机制，它实现了自动解决软件包之间的依赖关系，但所有的软件包均由集中的YUM软件仓库提供。因此，与RPM包管理不同的是，YUM是无法直接使用的，在使用YUM之前必须先构建YUM软件仓库。YUM使用最常见的C/S结构，YUM软件包仓库实际上就是指的Server端，Server端由两部分组成，除了包含众多的软件包，还包含仓库数据文件，仓库数据文件用于记录众多软件包的状态信息，类似于菜单的作用。在ISO镜像中，仓库数据文件是自带的，存放在`/mnt/iso/repodata/`路径下

YUM的搭建一般分为两种模式：本地YUM仓库和远端YUM仓库，本地YUM仓库将Server端和Client端集中存放在本机机器上，无需网络连接；远端YUM仓库则需要通过FTP协议或HTTP协议将软件包从Server端下载到本地进行安装，在使用YUM安装软件包时，默认情况下会跟用户再次确认是否安装软件，此时用户可以选择确认安装、拒绝安装或仅下载软件包到本地但不安装

### 本地YUM仓库

本地YUM仓库表示YUM的Server端与Client端都处于机器本地，避免通过网络传输数据

1. 挂载本地镜像

   ```bash
   [root@localhost ~]# mkdir /mnt/iso/
   [root@localhost ~]# mount /dev/sr0 /mnt/iso/
   ```

2. 新建YUM配置文件

   ``` bash
   [root@localhost ~]# \rm /etc/yum.repos.d/*        # 删除自带的.repo配置文件，任一一个有问题的.repo文件都会影响到YUM
   [root@localhost ~]# vi /etc/yum.repos.d/local.repo
   [local]         # 自定义YUM源名称，具备唯一性
   name = Local CDROM    # YUM源的描述，非必选项
   baseurl = file:///mnt/iso/    # ISO镜像的挂载点路径
   enabled = 1     # 启用此YUM源
   gpgcheck = 0    # 不验证RPM包的签名信息
   #gpgkey =       # 用于RPM软件包验证的密钥文件，不启用验证的情况下无需配置此选项
   ```

3. 验证

   ```bash
   [root@localhost ~]# yum repolist    # 列出系统可用的所有YUM仓库
   ```

4. 安装软件包

   ```bash
   [root@localhost ~]# yum install -y httpd    # 默认情况下YUM检测软件包的依赖关系后会交互式确认是否需要安装，-y参数表示取消交换式确认
   [root@localhost ~]# yum reinstall -y httpd    # 覆盖性的重新安装，某些场景下误操作删除了某个软件包中的可执行程序时，再次安装该软件包会提示已安装，此时就需要覆盖安装，使软件包重新生成可执行程序
   ```
   
5. 验证软件包是否安装成功

   ```bash
   [root@localhost ~]# rpm -q httpd
   ```

   RPM和YUM两个工具是结合使用的，一般情况下使用YUM安装/卸载软件包，通过RPM确认软件包的状态信息

6. 卸载软件包

   ```bash
   [root@localhost ~]# yum remove httpd
   [root@localhost ~]# yum erase httpd    # 卸载软件包及其配置文件
   ```
   
   在安装httpd软件包时，YUM还另外安装了4个依赖包，但卸载软件包时，在CentOS 7版本采用保守策略，如果这4个依赖包在脱离httpd软件的情况下也能够正常运行，则YUM卸载httpd软件时不会连同依赖包一起卸载。如果使用YUM在卸载A软件包时，A软件作为B软件的依赖包，卸载A软件后会影响B软件的正常运行，那么YUM会连同B和A两个软件一起卸载，因此卸载软件包时不建议直接使用-y参数，因为大多数情况下可能无法确定要卸载的软件包背后有多少依赖包会连同一起卸载

### YUM指令解析

```bash
# 查询操作，yum的查询操作是基于整个软件仓库的查询
yum list            # 列出YUM仓库中的所有软件
yum list ftp        # 查找YUM仓库中名为ftp的软件，使用list查询软件是严格匹配软件名称
yum search ftp      # 查找YUM仓库中名为ftp的软件，使用search查询软件是模糊匹配软件，此处“模糊匹配”并非只匹配软件名，只要软件能够实现相应功能的也会被匹配。以ftp为例，search ftp会匹配到curl工具，因为curl工具会使用到ftp功能
yum provides ftp    # 通过命令或文件逆向查询命令所属的软件包，与rpm -qf不同的是，YUM基于软件仓库的查询，不仅是只针对已安装的软件包进行查询

# 清空缓存
yum clean all       # 之后首次yum repolist时才会去读取YUM配置文件，之后YUM会将数据缓存在内存中。当YUM配置文件被修改后，就需要清空YUM缓存，使YUM重新读取配置文件
```
