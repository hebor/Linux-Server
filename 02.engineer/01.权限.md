# 权限

缺乏安全性的系统不是完整的系统，系统中必须有一套能够保护文件免遭非授权用户浏览或修改的机制，Linux沿用了Unix文件权限的办法，权限是针对数据进行设置的，用户或用户组根据每个数据的安全性设置来访问数据。Linux系统的权限只对普通用户生效，root账户可以无视任何权限，实现任意操作

## 基本权限

默认情况下，一个数据的所有者是创建该文件的用户、所属组是该用户的基本组，既不属于所有者也不属于所属组的用户就属于其他用户。所属组可以是创所有者的基本组，也可以是管理员创建的附加组

- 访问权限
  - 读取：允许查看内容 - r
  - 写入：允许修改内容 - w
  - 可执行：允许运行和切换 - x
- 归属关系
  - 所有者（属主）：拥有此文件/目录的用户 - u
  - 所属组（数组）：拥有此文件/目录的用户组 - g
  - 其他用户：除所有者、所属组以外的其他用户 - o

### 文件权限

```bash
[root@localhost ~]# ls -l /etc/passwd
    -      rw-r--r--.    1     root  root    892     Jun 14 06:05  /etc/passwd
[档案类型]  [  权限   ] [硬链接] [属主] [属组] [文件大小] [   修改日期  ] [   文件名  ]
```

**文件权限解析**

- 档案类型

  档案类型分为多种类型，比较常见的档案类型包括:`-`文件、`d`目录、`l`链接文件、`b`块设备，其中块设备在`/dev/`目录下比较常见

- 权限

  权限部分实际上被分为4组：`[rw-][r--][r--][.]`，从左到右分别代表着属主权限、属组权限、其他用户权限、ACL策略权限。除ACL策略权限以外，其他权限以3个字符为一组，每组权限都是`[rwx]`三个参数的组合，这三个权限排序位置不会产生变化；当ACL策略为空时以`[.]`表示，ACL策略不为空时以`[+]`表示

  在Linux系统下，`[rwx]`机制同时支持字符表示法与数字表示法两种形式，三种权限各自的数字表示分别是`r=4、w=2、x=1`，在修改文件权限时可以直接使用数字表示法

- 硬链接

  硬链接允许多个文件名指向同一个文件，本质上是对一个文件的多个引用，通过任一文件名即可修改文件内容，并同步到其他关联的文件名。硬链接数量指此文件存在多少个关联的文件名

- 文件大小

  显示单位为bytes

**修改文件权限**

```bash
# 数字表示法修改权限
[root@localhost ~]# chmod 777 ~/.bashrc    # 为此文件设置所有人都具备所有权限
[root@localhost ~]# chmod 644 ~/.bashrc    # 将此文件恢复为[rw-r--r--]权限

# 字符表示法修改权限
[root@localhost ~]# chmod u=rwx,go=rx ~/.bashrc    # 为此文件设置[rwxr-xr-x]权限
[root@localhost ~]# chmod a+w ~/.bashrc    # 将此文件的所有归属关系添加w权限
	-R：递归修改权限
	
# 修改数据属主、属组
[root@localhost ~]# chown hebor:root /home/hebor/    # 将指定目录属主修改为hebor、属组修改为root
[root@localhost ~]# chown .hebor /home/hebor/    # 将指定目录属组修改为hebor。间隔符既可以使用`:`、也可以使用`.`
```

chown指定更改文件所属用户和所属组时，如果要修改所属组，但又未指定所属组名，例如`chown hebor.  /etc/hosts`，此时会判定所属组修改为目标用户的主属组；字符表示法修改权限的组合样式非常多，可以通过以下方式组合设置：

| chmod | u<br />g<br />o<br />a | +（追加权限）<br />-（移除权限）<br />=（定义权限） | 文件或目录 |
| ----- | ---------------------- | --------------------------------------------------- | ---------- |

#### 用户与文件的权限判断

对于某一个用户对于某个数据有没有操作权限，两个步骤即可判断：首先检查数据的属主、属组、权限信息，其次查看用户的账户、属组信息。根据用户的账户、属组信息可以判断出，该用户是否为数据的属主、该用户是否处于数据的属组中，两者都不是的话，该用户对数据而言就属于其他人，再根据数据的权限信息即可判断用户是否具备操作权限

在上述步骤中，用户权限的匹配是有优先级顺序的，优先顺序是属主>属组>其他人，并遵循匹配即停止原则。例如，一个数据的属主和属组都是user01，当user01要操作此数据时按照优先匹配顺序会具备属主的权限，即便属组拥有更高权限，按照匹配即停止原则和有限匹配顺序，user01用户也只会匹配到属主的权限

需要注意的是，理论上在属主、属组、其他用户三个归属关系中，只需要任意一个归属关系具备权限，那么用户就具备操作权限。某些场景下为了使用户具备操作权限，会修改数据的权限信息，属主、其他用户的权限信息位修改后都是立即生效的，但属组的权限信息位修改后不是立即生效，需要用户重新登录shell会话生效

当普通用户作为数据的属主时，对于数据的各种权限测试就会产生一些奇怪的组合现象：

1. 当文件权限为`000`时，属主理论上没有写入权限，但通过vim写入后强制保存，也是能够成功覆盖写入的
2. 当文件权限为`400`时，通过vim写入后强制保存，可以达到追加写入、读写成功的效果
3. 当文件权限为`200`时，通过vim写入后强制保存只能实现覆盖写入，通过重定向可以实现覆盖写入或追加写入
4. 当文件权限为`100`时，通过vim写入后强制保存可以实现覆盖写入，但属主仍无法执行文件，需要搭配读权限

以上权限仅作为测试，不符合实际使用需求

#### 默认文件权限umask

umask命令用于设置所创建的文件和目录的默认权限，umask默认的值是0022，对文件来说全权限的值是666、对目录来说全权限的值是777，那么创建文件或目录时，umask的值会作为掩码，例如创建一个文件，默认权限是666，666减去umask的掩码值022后，就变成了644；通常umask的值会设置在/etc/profile文件中，也有一些发行版会将umask值设置在/etc/login.defs文件中，通过umask命令也可以直接修改默认值

```bash
[root@localhost ~]# umask 077    # 临时修改umask值
[root@localhost ~]# umask        # 查看umask值
	-S：以字符表示法展示新建目录所具备的权限
```

### 目录权限

即便文件与目录具备同样的权限，其表现形式可能也有差别：


1. 当目录权限为`000`时，属主无任何权限，无法执行任何操作
2. 当目录权限为`400`时，属主能显示目录下的文件名，但无法显示文件的属性信息
3. 当目录权限为`200`时，属主无任何权限，无法执行任何操作
4. 当目录权限为`100`时，属主仅能够进入目录
5. 当目录权限为`500`时，属主能显示目录下的文件详细信息
6. 当目录权限为`300`时，属主具备新建和删除权限

一般情况下，目录的读取和执行权限是组合授权的，单独只授予其中一个权限会导致上述异常。**一个目录如果要能够正常查看 和 正常修改数据，都需要执行权限配合。**Linux对于目录的写入权限的定义是，能够创建、删除、修改目录下的内容，但不可修改目录本身的属性。

## 特殊权限

特殊权限是脱离`[rwx]`以外的权限，部分教程也会将其称为附加权限，特殊权限的展示形式是叠加在u、g、o的基本权限位的分组上，它被用于传递程序执行身份、限制目录写入权限等。特殊权限一共有3个：

- Set UID（SUID）：

  占用属主的x位，显示为s或S，取决于属主是否有x权限。此权限仅针对二进制程序有效，且普通用户本身要对二进制程序有x权限。当普通用户执行二进制程序时，执行者将会以程序属主的身份执行程序。passwd命令就是最佳示例，用户的密码都是记录在`/etc/shadow`文件中，普通用户没有权限修改，但普通用户仍能够通过passwd命令修改自身的密码，这就是SUID实现的功能，在程序执行过程中能够以程序属主的身份运行，也就是以root身份运行

- Set GID（SGID）

  占用属组的x位，显示为s或S。属组具备x权限时以s显示，不具备x权限时以S显示，并且x权限与s权限的配置没有先后顺序要求，可以先配置S权限再配置x权限，此权限主要对目录有效。对文件而言，程序会以属组的权限运行；对目录而言，目录下新建的文件会自动继承此目录的属组身份作为文件的默认属组

- Sticky Bit（粘滞位）：进程结束后文件还驻留（粘着）在内存中

  占用其他人的x位，显示为t或T。属组具备x权限时以t显示，不具备x权限时以T显示，此权限主要对目录有效。此权限主要用于共享目录场景下限制普通用户滥用写入权限，在设置了t权限的目录下，普通用户创建的文件或目录，只能被该用户或root用户修改，其他用户无法删除该用户创建的文件或目录。在CentOS系统下，只有`/tmp`目录默认就具备t权限

特殊权限位同样也有数字表示法：`SUID=4、SGID=2、Sticky=1`

**特殊权限命令解析**

```bash
# SGID
[root@localhost ~]# chmod g+s /home/hebor/    # 同样可以通过chmod 2755 /home/hebor/ 实现
[root@localhost ~]# ls -ld /home/hebor/
drwxr-sr-x. 2 hebor hebor 132 Jun 15 16:36 /home/hebor/
[root@localhost ~]# touch /home/hebor/test.txt
[root@localhost ~]# ls -l /home/hebor/test.txt 
-rw-r--r--. 1 root hebor 0 Jun 15 16:36 /home/hebor/test.txt

# Sticky Bit
chmod 777 /home/public/
chmod o+t /home/public/    # 同样可以通过chmod 1777 /home/hebor/ 实现
ls -ld /home/public/
```

## ACL策略管理

基本权限是Linux系统上应用最多的权限，但它也具备其局限性，任何用户都只属于三种角色：属主、属组、其他人，无法实现更精细的控制。ACL访问策略可以实现针对个别普通用户、个别用户组设置独立的权限，大多数挂载ext3/4、xfs的文件系统默认已支持ACL访问策略。在数据同时设置有基本权限和ACL策略的情况下，优先以ACL策略生效

1. 设置ACL

   ```bash
   [root@localhost ~]# setfacl -m u:hebor:--- /etc/passwd    # 为指定用户设置无权限
   	-m：定义一条ACL策略
   	-x：清除指定的ACL策略
   	-b：清除已设置的所有ACL策略
   	-R：递归设置ACL策略。此选项时需要结合-m选项使用，且-Rm顺序不可颠倒
   [root@localhost ~]# setfacl -m g:test01:rwx /etc/passwd    # 为指定用户组设置所有权限
   [root@localhost ~]# setfacl -x u:hebor /etc/passwd         # 删除ACL
   [root@localhost ~]# setfacl -b /etc/passwd                 # 清空ACL
   ```

2. 查看ACL

   ```bash
   [root@localhost ~]# getfacl /etc/passwd
   ```

# 进程管理

进程与程序区别在于，程序指的是静态的没有运行的代码，进程指的是动态执行的代码，前者存放在磁盘中，后者会占用CPU与内存资源，真正提供软件功能的是进程，程序在运行之后才能成为进程。进程又被分为父进程和子进程，所有的子进程一定是由其父进程拉起的，一个父进程下可以拉起N个子进程，父进程与子进程之间是一个巨大的树型结构，每个进程在系统上都有一个唯一编号PID

## 命令解析

**pstree指令**

```bash
pstree    # 查看系统进程树
	-a：显示完整的命令行
	-p：列出对应进程的PID号
pstree hebor    # 查看指定用户启用的进程
```

其中systemd处于进程树树根位置，systemd也号称是所有进程的父进程。正常情况下，父进程在终止之前一定会先自动终止其下面的子进程，这个动作的本意是为了释放更多系统资源，因此，systemd进程与系统中的`/`同等重要，终止systemd进程几乎与重启相差无几。systemd作为Linux系统启动后的第一个进程，其PID永远为1

**ps指令**

```bash
ps
	aux：显示当前终端所有进程（a）、当前用户所在终端下的进程（x）、以用户格式输出（u）
	-elf：显示系统内所有进程（-e）、以长格式输出信息（-l）、包括最完整的进程信息（-f）
	
USER    PID         %CPU            %MEM          VSZ      RSS     TTY   STAT    START       TIME     COMMAND
用户    进程ID   占用CPU的百分比   占用内存的百分比   虚拟内存   固定内存   终端   状态   起始时间   CPU处理时间   程序指令
```

ps指令的两种组合参数各有特点，aux显示的进程信息非常详细、elf会显示父进程的信息，PPID为父进程的PID

**top指令**

top指令是一个动态交互式工具，P键按CPU使用率排序、M键按内存使用率排序

```bash
top
	-d：刷新时间，以秒为单位
	
top - 14:56:00   up  2:27,          1 user,    load average: 1.13, 0.91, 0.58
      当前时间  系统已运行2小时27分  1个用户正在登陆  CPU的负载量：1分钟、5分钟、15分钟
Tasks: 270 total,   1 running,  268 sleeping,   0 stopped,   1 zombie
        总进程数    正在运行进程数  后台挂起进程数     进程停止数    僵尸进程数
%Cpu(s):  6.6 us,  4.0 sy,  0.0 ni, 89.0 id,  0.1 wa,  0.0 hi,  0.2 si,  0.0 st 
MiB Mem :  11661.4 total,   6137.8 free,   4558.3 used,   2037.7 buff/cache     
MiB Swap:   4096.0 total,   2223.0 free,   1873.0 used.   7103.1 avail Mem
```

top工具统计的用户数量并不是按照用户名来算的，是按照会话数量计算的。例如，root用户分别通过图形化、Xshell远程工具、命令行字符界面进行登陆，三个会话在top工具中会显示为3个用户正在登陆，即便在图形化窗口中再开启一个终端窗口，这也算一个登陆用户

后台挂起进程的是节省系统资源的机制，业务压力不大时不需要过多的进程占用系统资源；僵尸进程指的是意外终止对外提供服务，但仍在占用系统资源的进程，因此僵尸进程也需要管理员手动终止。除了top命令能看到的这两种进程，还有一种异常进程被称为孤儿进程，孤儿进程指的是父进程在终止其子进程时遗漏的子进程，孤儿进程在失去父进程的约束后，会认为整个系统资源都是可用的，可能会大量占用CPU、内存资源

CentOS 7系列的systemd进程会自动查找系统中的孤儿进程，并将其终止

**pgrep指令**

```bash
pgrep -xl systemd
	-l：输出进程名，而不仅仅是PID。常用选项
	-U：检索指定用户的进程
	-x：精确匹配完整的进程名
```

pgrep指令显示的信息不如pstree指令的信息直观，因此一般用pstree指令比较多

## 控制进程

xeyes是Linux系统上的一个图形化小程序，它会在屏幕上显示一双眼睛，并跟随鼠标指针移动

**快捷键**

1. &符号

   将进程运行到后台

   ```bash
   xeyes &
   ```

2. Ctrl+z组合键

   挂起（暂停）当前进程并将进程转到后台

   ```bash
   xeyes
   Ctrl+z
   ```

通过测试`&`符号与`Ctrl+z`组合键可以看出两者区别，`&`符号必须在命令行中即将要运行的程序尾部添加，也就是在程序运行之前添加`&`符号，`Ctrl+z`组合键则是在程序运行之后使用，也就是对进程生效；`&`符号是将程序运行在后台，`Ctrl+z`组合键是将进程在后台挂起（暂停），可以看到xeyes被挂起后，眼睛不会在跟随鼠标指针移动

**jobs指令**

查询后台进程列表

```bash
jobs -l
	-l：在正常信息的基础上列出进程 ID
```

**fg指令**

将后台任务恢复到前台运行，序号表示后台进程的编号

```bash
xeyes &
[1] 74701
fg 1
```

**bg指令**

激活后台被挂起的任务，bg指令一般配合`ctrl+z`使用

```bash
xeyes
^Z
[2]+  已停止               xeyes
bg 2
```

**nohup指令**

nohup用于在系统后台不挂断地运行命令，退出终端不影响程序的运行。默认情况下不使用重定向时，nohup会将挂起的命令输出结果保存到nohup.out文件中，这个文件默认保存在当前目录下，如果当前目录下的nohup.out文件不可写，输出重定向到$HOME/nohup.out文件中

nohup本身没有将进程挂到后台运行的功能，它能保证的是不挂断的运行命令，只有配合&符使用时，才能够实现在系统后台不挂断地运行命令，如果nohup不搭配&符使用，直接关闭远程窗口仍会导致nohup进程被终止，建议的方式是先使用exit退出远程连接再关闭远程窗口

```shell
nohup ping www.baidu.com &
nohup ping www.baidu.com 2>&1 &
```

## 终止进程

1. **Ctrl+c组合键**

   用于中断当前前台的命令程序

2. **kill指令**

   kill指令通过PID杀死进程

   ```bash
   xeyes &
   [1] 93667
   
   kill -9 93667
   	-9：强制杀死进程
   ```

3. **killall指令**

   killall指令通过进程名称杀死进程

   ```bash
   xeyes &
   [1] 94590
   xeyes &
   [2] 94597
   
   killall -9 xeyes
   ```

4. **pkill指令**

   ```bash
   pkill -9 查找条件
   ```

pkill指令慎用，pkill指令的查找条件并非精确匹配。例如，`pkill -9 a`这条指令表示只要进程名称内包含`a`字符的进程都会被杀死。建议使用killall指令，killall指令会严格匹配进程名称
